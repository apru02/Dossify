# AI_NOTES

## Tools and how the work was split

- **AI:** Claude Code (desktop app) running **Claude Opus 5.5**, for the whole project.
- **Context files:** [`CLAUDE.md`](CLAUDE.md) (architecture, tenancy rules, security invariants, conventions) and [`AGENTS.md`](AGENTS.md) (generated by Next.js 16; tells the AI to read the bundled Next docs, because APIs like `middleware.ts` → `proxy.ts` changed after most training data).
- **Running log:** [`docs/dev-log.md`](docs/dev-log.md) records decisions and bugs as they happened. This file is the summary.

**Me:** product and architecture decisions, branding (logo, palette, Inter), all third-party setup (Supabase, Google OAuth, Vercel, Slack app, SMTP), running migrations, testing every signed-in flow in the real app, reviewing, merging, and pushing.

**The AI:** code, SQL migrations and RLS, tests, setup guides, and small experiments (similarity calibration, model availability, prompt checks against live Gemini).

The AI never signed in to my app: it won't create accounts on a remote Supabase project. So everything behind login was verified by me, which matters for the bugs below.

## Decisions I made

1. **Two account types.** *Personal* (exactly one member) and *Organization* (invite teammates, roles). An organization is the tenant and workspaces belong to it. The one-member rule for personal accounts is enforced by a DB trigger, not just the UI.
2. **Isolation lives in the database.** One shared `document_chunks` table, with `WHERE workspace_id = …` inside the vector query. That query runs as the signed-in user, so RLS applies too, and composite foreign keys stop a chunk from being tagged with the wrong workspace. No service-role key in the app.
3. **Multiple chat sessions per workspace.** Conversation memory is per session, while retrieval always covers the whole workspace's documents.
4. **Per-workspace Slack ("Add to Slack").** Every customer connects their own channel, rather than the app posting to one channel I own. See the wrong turn below.
5. **Standard SaaS invites.** Email invitations with hashed, expiring tokens. Accepting requires the invited email address. Admins can resend, revoke, change roles and remove members.
6. **Stack:** Next.js 16, Supabase (Auth, Postgres, pgvector), Gemini (free tier), Vercel. The AI proposed it; I chose it because everything is free with no card.

## Where the AI was wrong

**1. Hardest wrong turn: one Slack webhook for the whole app.** When I asked for Slack, the AI built `send_summary` on a single `SLACK_WEBHOOK_URL` environment variable, and it even gave me instructions to create "my" webhook. In a multi-tenant product that means every customer's summaries land in *my* channel. I pushed back:

> "Why I need to create slack webhook for my channel only, It should be like any user can integrate their own slack channels in dossify"

The fix was a real OAuth v2 install per workspace (`incoming-webhook` scope). That surfaced a harder problem the first design had hidden: where to store each tenant's webhook secret when the app deliberately has no service-role key. Anything the server can read, a workspace member could read through the API. The solution is application-level **AES-256-GCM encryption**:
- The key lives only in the server environment.
- The workspace id is bound as associated data, so a ciphertext copied into another workspace won't decrypt.
- Only admins can connect or disconnect.
- A check constraint rejects plaintext.

**Lesson:** the AI defaulted to the quickest single-tenant shortcut even though isolation was the core requirement written in `CLAUDE.md`. It should have asked "one channel for the app, or one per customer?" before building.

**2. The chat logo stretched on long answers.** The small Dossify logo next to each answer rendered as a tall stretched sliver on long replies. I found it from a screenshot; the AI couldn't see it, because it never loaded a signed-in page.
- **Cause:** Tailwind's base styles set `img { height: auto }`, and flex rows stretch their items by default, so the image grew to the answer's height.
- **Fix:** a fixed inline width and height on the logo component (so no layout can distort it) and top alignment in chat.
- **Verification:** the AI checked the fix by putting the real logo element into a 400px-tall flex row on a public page.

**Lesson:** "typecheck and build pass" says nothing about layout. The UI the AI couldn't see was exactly where bugs got through.

**3. Smaller wrong turns:**
- **One permanent chat thread.** The AI made one per workspace; I asked for sessions.
- **Stalled push.** When a `git push` hung, the AI worked around my credential setup instead of stopping, just as I wrote "leave it, I will push".
- **Old model names.** The AI's first choices came from training data: `gemini-2.5-flash` returned **404, retired for new keys**, and `gemini-flash-latest` returned **503** on 3 of 4 calls. A short live test changed the plan to a fallback chain of `-latest` models.

**Caught by the tests the AI wrote (worth keeping that habit):**
- Slack's plain-text notification line was unescaped, so an injected `<!here>` could have pinged a whole channel.
- pdf.js empties the byte array it's given.
- A 3-page PDF was cited as "pp. 1–3" for a fact on page 2, fixed by breaking chunks at every page.
- A Vitest `beforeEach(() => mock.mockReset())` quietly ran the mock as a cleanup hook and cost real debugging time.

## Learnings and feedback

- **Give the AI a way to see the signed-in app.** Next time I'd set up a local Supabase with a seeded test user plus Playwright from day one. The two bugs I had to catch myself were both UI-only.
- **State tenancy expectations for every feature, not just once.** "Isolation" in `CLAUDE.md` wasn't enough to stop a single-tenant Slack design. I now read each plan with one question in mind: *whose data or channel is this?*
- **Measure instead of trusting training data.** Similarity thresholds (answerable 0.69–0.78 vs off-topic 0.50–0.57) and model availability were both measured. The measurements overturned the AI's first assumptions every time.
- **Tests against the real SQL paid off.** Running the actual migrations in PGlite (Postgres and pgvector in memory) made isolation, RLS and invite rules provable without a Supabase project: 108 offline tests plus 12 live Gemini tests.
- **Feedback for the AI:** ask one clarifying question before an architecture choice that affects tenants; don't work around user-owned steps like pushing; say plainly when something wasn't verified in the UI. It was good at this last one: every change came with a note of what it couldn't check.
